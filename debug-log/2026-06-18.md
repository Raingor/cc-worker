# 追加分析功能（Re-analyze）

## 需求
分析完成的记录中，用户可以直接输入补充需求，让 AI 结合原始数据重新分析，无需重新发邮件。

## 改动清单

### 1. `server/analysis_store.py` — 数据库扩展
- 新增 `_migrate_db()` 函数，安全添加 3 个新列：
  - `email_body_full` — 完整邮件正文（最多 10000 字）
  - `attachment_analysis` — 附件分析结果 JSON（用于重建 prompt）
  - `user_instructions` — 用户补充需求（保存历史）
- `create_record()` 现在保存 `email_body_full` 和 `attachment_analysis`
- 新增 `update_response()` 更新 AI 响应和用户指令
- `_row_to_dict()` 解析新 JSON 字段 + 默认值兜底

### 2. `server/app.py` — 新增 API + 数据补全
- 初始分析（`email_ai_analyze`）现在同时保存 `email_body_full` 和 `attachment_analysis`
- 新增 `POST /v1/analysis/<id>/reanalyze`：
  - 接收 `{ "instructions": "..." }`
  - 从数据库重建原始 prompt（邮件信息 + 附件分析 + 上次结果）
  - 注入用户补充需求
  - 调用 AI API 重新分析
  - 更新记录的 `ai_response` 和 `user_instructions`

### 3. `web/assets/analysis.js` — 前端 UI
- 记录卡片新增 "🔄 追加分析" 按钮
- 点击展开 textarea 输入框 + "🚀 开始重新分析" 按钮
- 新增函数：
  - `toggleReanalyze(id)` — 显示/隐藏输入区域
  - `reanalyzeAnalysis(id)` — 调用 API，显示状态，刷新列表
- 空输入校验（红色边框提示）
- 分析完成后自动刷新列表 + 刷新详情

### 4. `web/assets/style.css` — 样式
- `.analysis-reanalyze-wrap` — 输入区域容器
- `.analysis-reanalyze-input` — textarea 样式（焦点变青）
- `.analysis-action-primary` — 主要按钮（青色背景）
- `.analysis-reanalyze-status` — 状态提示（info/success/error）

## 向后兼容
- 旧记录无 `email_body_full` → 回退到 `email_body_preview`
- 旧记录无 `attachment_analysis` → 显示 "(无 Excel 附件)"
- 数据库迁移使用 `ALTER TABLE ADD COLUMN` + try/except，安全重复执行

## 验证方式
1. 打开一个已有分析记录的详情
2. 点击「追加分析」，输入需求
3. 点击「开始重新分析」
4. 等待 AI 返回结果，卡片预览和详情自动刷新

# PDF转Excel 支持无边框表格

## 问题
工具箱的「PDF转Excel」只支持有边框表格（依赖 pdfplumber 的 `extract_tables()`）。
