# 2026-10-29 · 留言／回复提交前必填名称

## 反馈与原因

用户从正式留言板截图指出：发布留言和回复时都应先留下名称。

原界面没有名称输入框，`web/assets/board.js` 的两个提交分支都固定传 `author: 'CC'`，因此所有新留言／回复都显示同一名称。现有 `/v1/board`、`/v1/board/<id>/replies` API 及 SQLite 已支持保存和返回作者，不需要数据库迁移。

## 修改

- 发布表单与每条回复表单均增加「你的名称 · 必填」输入框，不预填 CC，也不持久化到浏览器。
- 名称与正文使用 required 及 trim 后的前端校验；空名称、仅空白名称或仅空白正文不发送请求。
- 提交实际填写并去除首尾空白的 `author`，名称最多 50 个字符。
- 回复改用原生 form／submit，与发布共享验证逻辑，支持浏览器原生无障碍提示；展开回复先聚焦名称。
- 成功提交后清空名称与内容，下次需要重新署名；失败保留草稿；取消回复清空草稿。
- 提交中防止重复请求；名称显示沿用 HTML 转义；历史作者和留言不修改。
- 维持 Quiet Workspace 的间距与配色，手机名称输入字号 16px；更新 CSS 与 board.js 的缓存版本。

## 验证

- `node --check web/assets/board.js`、`git diff --check` 通过。
- 320、390、768、1440px 四个 viewport 各通过 24 项浏览器检查（共 96 项）：缺失／空白姓名拦截、实际姓名与正文发送、署名显示、历史作者保留、成功清空、失败保留、取消清空、重复提交拦截、名称 HTML 转义及标签关联等。
- 四尺寸的发布／展开回复表单均无水平溢出，无 JavaScript 错误；手机名称输入实际字号为 16px。
- axe-core 4.10.3 在发布及展开回复表单执行 WCAG A／AA 常用自动规则，未报告违规。
- 所有提交回归均拦截为本地 fixture，未向正式 API 发布、回复或删除测试内容。

## 范围

本次必填规则针对 Web 表单；API 既有默认作者逻辑保持兼容，不提供身份认证或冒名防护。没有改动后端、数据库或旧作者记录。
