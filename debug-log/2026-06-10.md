# 部署工具箱后端支持

## 问题
工具箱中的 PDF分割、PDF压缩、OCR识别、表格提取 4 个工具需要后端支持但未实现。

## 服务端环境
- 服务器: 120.79.7.233 (CentOS 7, 1GB RAM)
- 原 Python: 3.6.8 (不支持 `from __future__ import annotations` 和 `list[dict]` 等语法)
- 部署方式: uWSGI + Nginx

## 过程

### 1. 安装系统依赖
```bash
yum install -y epel-release
yum install -y tesseract tesseract-langpack-chi_sim  # OCR 引擎
yum install -y poppler-utils                         # pdfseparate (PDF分割)
yum install -y ghostscript                           # gs (PDF压缩)
```

### 2. Python 版本升级
Python 3.6 不支持 `from __future__ import annotations` 和 `X | Y` 联合类型语法。
全部 `from __future__ import annotations` 和类型标注改为 `X | None`。

最终决定使用 SCL 的 Python 3.8:
```bash
yum install -y centos-release-scl
yum install -y rh-python38-python rh-python38-python-devel
/opt/rh/rh-python38/root/usr/bin/python3.8 -m venv venv
```

### 3. urllib3 兼容性问题
Python 3.8 的 urllib3 v2 需要 OpenSSL 1.1.1+，但 CentOS 7 只有 1.0.2。
降级安装 urllib3 v1:
```bash
pip install "urllib3<2"
```

### 4. 添加的 API 端点

| 端点 | 方法 | 说明 | 依赖 |
|------|------|------|------|
| `/v1/toolbox/pdf-split` | POST | PDF分割为单页，返回 ZIP | poppler-utils (pdfseparate) |
| `/v1/toolbox/pdf-compress` | POST | PDF压缩 | ghostscript (gs) |
| `/v1/toolbox/ocr` | POST | OCR文字识别，返回 JSON | tesseract + pypdfium2 |
| `/v1/toolbox/table-extract` | POST | 表格提取，返回 Excel | pdfplumber |

### 5. 前端更新
替换了 toolbox.js 中 4 个占位符 UI，改为真实的文件上传 + API 调用 UI：
- PDF分割: 已有代码，未变动
- PDF压缩: 新增拖拽上传 UI，调用 `/v1/toolbox/pdf-compress`
- OCR: 新增拖拽上传 UI，支持 PDF/图片，结果内联显示 + 复制按钮
- 表格提取: 新增拖拽上传 UI，调用 `/v1/toolbox/table-extract`

### 6. 验证结果
所有 4 个端点通过 https://api.sz-hrhb.com 验证正常：
- PDF分割: HTTP 200, 返回 ZIP
- PDF压缩: HTTP 200, 返回压缩 PDF
- OCR: `{"success":true,"text":"--- 第1页 ---\nDummy PDF file"}`
- 表格提取: 返回 "No tables found" (正确行为)
- 错误处理: 无文件返回 400, 不支持格式返回 400, 未授权返回 401

## 注意事项
- Office→PDF 暂未实现 (需要 LibreOffice，1GB 内存不足)
- tesseract 图片 OCR 在 CentOS 7 的 PIL 默认字体下渲染有问题，PDF OCR 正常
- 因 Python 3.8 urllib3 与 CentOS 7 OpenSSL 不兼容，需保持 `urllib3<2`
