# 2026-08-12 PDF转Excel 扫描版支持（OCR 兜底）

## 问题
用户上传扫描版 PO PDF（`PO#28419...`，图片型 PDF 无文本层），PDF转Excel 报错
"No tables found in the PDF"。该 PDF 结构特殊：pdfplumber 读出的**页数为 0**（页面树异常），
实际内容全是 JPEG 图像（2550x3266 DCTDecode）。

## 根因
`pdf-to-excel` 端点只支持两种提取：
1. `page.extract_tables()`（有边框表格）
2. `_borderless_tables()`（文字位置检测）

两者都依赖 PDF 有**文本层**。扫描版 PDF 无文字 → 全部失败。

## 解决方案（server/app.py）
新增 OCR 兜底流程（当文本层提取为空时）：

1. **渲染**：`pypdfium2` 渲染每页（scale=2）
2. **OCR**：`tesseract ... hocr`（chi_sim+eng）→ 解析 `ocrx_word` 的 bbox 得到带坐标单词
3. **重建表格**（`_detect_table_from_words`）：
   - 行带聚类：top 差 <12pt 合并为一行
   - 参考行：列簇最多者（并列取靠后，数据行通常比表头准）
   - **数字簇按词拆分**：数量+料号粘连（OCR 框重叠）时每词一列
   - 列边界取相邻簇（左缘+右缘）/2
   - 仅描述列的换行合并到上一行
4. **表格区域过滤**（`_table_region`）：
   - 明细行 = 首列纯数字 + 第二列含数字 + 第三列非空
   - 表头 = 首条明细上方最近 ≥4 列的行
   - 剔除 PO 抬头/装箱说明等噪音行

## 踩坑记录

### 1. 渲染图片没 save（最关键的 bug）
`_ocr_words_hocr` 里 `tempfile.mkstemp()` 创建的是**空文件**，
忘记调用 `img.save(img_path)`，导致 tesseract 报
`Error in pixReadMem: size < 12`（读到 0 字节）→ 快速失败返回 0 词。

### 2. pkill -f "uwsgi" 自杀
远程命令 `pkill -f "uwsgi.*5001"` 会匹配**包含该字符串的 ssh 会话自身**，
导致 exit 255 命令中断、uwsgi 没真正重启，新代码一直没生效。
**解决**：用 `PAT="venv/bin/u"ws"gi"` 拆串避免匹配，或先 `pgrep` 再按 PID kill。
部署脚本 setup-server-remote.sh 里的 `pkill -f "uwsgi.*5001"` 有同样风险，
在 ssh 里执行时不会匹配（脚本内容不在 ssh 命令行），但手动操作时注意。

### 3. 部署后需彻底重启
rsync 新代码后，若旧 uwsgi 进程没杀干净，会继续跑内存中的旧代码
（表现为改了什么都没效果）。先 `pgrep -f venv/bin/uwsgi` 确认 0 残留再启动。

## 验证
- 上传原 PO PDF → HTTP 200，78.7s（OCR 2 页），生成 2 个 sheet 的 xlsx
- 第1页：表头 + 5 条明细（数量/料号/描述/单价/金额）
- 第2页：表头 + 1 条明细 + 合计行
- OCR 噪音不可避免（如 0.1680 识别为 0′l680），tesseract 3.04 所限

## 遗留
- tesseract 3.04 每页 OCR 约 55s，2 页约 110s（请求已实测 78s）
- 可考虑升级 tesseract 4.x（LSTM 识别率更高、支持 TSV 坐标输出）
