# 2026-08-05 部署踩坑：uwsgi 端口占用 + SSH 别名

## 背景
PIR 删除任务从周四移到周二、周四新增下车间检查，更新 `day_reminders.json` + `declarativeAgent.json` 后部署服务器端。

## 问题 1：deploy-api.sh 后 API 502

### 现象
部署后 `https://api.sz-hrhb.com/health` 返回 502，uwsgi 无进程、5001 端口无监听。

### 根因
`setup-server-remote.sh` 里 `pkill -f "uwsgi.*5001"` 后**立即**启动新 uwsgi，
旧实例端口未及时释放 → 新实例 `bind(): Address already in use` → 直接退出，无守护进程接管。

### 解决
等端口释放后手动重启：
```bash
cd /home/www/html/cc-worker-api
nohup ./venv/bin/uwsgi --ini uwsgi.ini > /dev/null 2>&1 &
# 验证：curl http://127.0.0.1:5001/health → 200
```
**预防**：后续在 setup 脚本 pkill 后加 `sleep 2`，或启动失败时重试。

## 问题 2：SSH 直连 120.79.7.233 认证失败

### 现象
`ssh root@120.79.7.233` → Permission denied；`ssh cc-worker` 正常。

### 根因
`~/.ssh/config` 中 `Host cc-worker` 配置了 `PubkeyAcceptedAlgorithms +ssh-rsa` / `HostKeyAlgorithms +ssh-rsa`，
服务器只接受 ssh-rsa 算法，直连时客户端默认不启用该算法 → RSA 密钥未提供 → 降级密码认证失败。

### 解决
部署时用别名覆盖：
```bash
REMOTE_HOST=cc-worker bash scripts/deploy-api.sh
```
