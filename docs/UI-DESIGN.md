# CC 工作台 · Quiet Workspace

## 设计方向

以「从容工作」为核心：米白画布、鼠尾草绿、细边框、中文衬线标题、清晰的内容层级。重点是增加空间、减少同时出现的控制项，而不是缩小文字塞进更多内容。

- 单一固定侧栏，分为「日常工作」与「效率与创作」。不再同时展示桌面菜单、Dock 和悬浮装饰。
- 页头提供当前位置、日期与专注模式；工作面板的三个分区使用页内导航。
- 工作面板：介绍与实时完成进度 → 工作清单 → 三列任务看板 → AI 总结。手机与窄平板将看板改成单列，不强迫横滑。
- 工具箱：九个工具的分类／搜索卡片；选择后进入独立操作区域，保留返回全部工具入口。
- Agnes：优先展示提示词及常用选项；模型／返回格式、对话参数使用可展开的高级设置。
- 邮件分析：一个主要操作，帮助默认折叠，历史记录与结果分区显示。
- 备忘录、留言板：限制阅读宽度，增加输入、内容与操作之间的间距。
- 保留五种配色，使用较深的柔和强调色；正文与辅助标签不能以低对比度换取轻盈感。

## 实作入口

| 文件 | 职责 |
|---|---|
| `web/index.html` | 页面骨架、导航、公共图标、静态分析页 |
| `web/assets/workspace.css` | 当前设计的 tokens、布局、组件覆盖、响应式、可访问性 |
| `web/assets/workspace.js` | 页内导航、日期、专注模式、键盘操作、移动端导航状态 |
| `web/assets/theme.js` | 配色与持久化 |
| `web/assets/dashboard.js` | 任务、进度、日历及总结 |
| `web/assets/toolbox.js` | 工具目录、筛选搜索及原有文件处理 |
| `web/assets/agnes.js` | 生成／对话界面与原有 API 交互 |

CSS 加载次序为 `animal-island.css` → `style.css` → `workspace.css`。前两者保留旧组件基础与兼容 tokens；**当前外观以 `workspace.css` 为准**。`mac-layout.css`、`layout-switcher.js`、`bear-corner.js` 不再由首页加载；不清除旧用户在 localStorage 内的主题／布局／壁纸资料。

请勿只修改旧样式文件后假设新页面一定生效。资源改动后同步更新 `index.html` 中的版本参数，避免旧 JS 与新页面混用。

## 验收要点

1. 六个功能页、九个工具都可以从界面进入；默认首页仍为今日任务。
2. 任务状态／新增／备注／删除、日历选日、历史总结入口不被外观改动破坏；任务状态变化后标题进度同步更新。
3. 工具筛选、搜索、空结果、上传、参数设置、返回目录都可操作。
4. 桌面测试 768、1024、1440、1920px；手机用真实 viewport emulation 测试 320、375、390px，不以桌面窗口最小宽度代替。
5. 每个内容区只保留一个主要纵向滚动容器，不能出现横向裁切；窄屏输入字体至少 16px，允许浏览器缩放。
6. 键盘可访问导航、上传、日期、主题；锁屏可以 Enter／空格解锁；隐藏侧栏不可获得键盘焦点。
7. 尊重减少动态效果设置。可用 axe-core 检查六个页面和九个工具的 WCAG A／AA 常见问题，但自动检查不能替代完整人工审核。
8. 浏览器回归用隔离上下文拦截全部 `/v1/` 请求并提供测试资料，禁止为了测试 UI 修改真实任务或触发付费生成。模拟资料不放入生产 `web/`。

本地静态预览：`python3 -m http.server 8086 --bind 127.0.0.1 --directory web`。本地 origin 如果未列入生产 API 的 CORS 白名单，任务加载会显示网络提示；这不等于生产 API 故障，不要为预览随意放宽生产跨域策略。
